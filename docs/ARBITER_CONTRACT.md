## Why this is a pointer

This repository implements the contract on the Akka runtime; it does not define
it. The contract binds four runtimes and its §8 acceptance test is byte
equivalence across them, so the definition cannot live inside any one
implementation.

The master carried no pointer here until now — the failure one step before
drift. Nothing in this repository named the contract, so the natural repair for
"the arbiter needs describing where it is implemented" was a local description,
and a local description becomes a second master.

§7's parallelism directive for this runtime is explicitly provisional: it
proposes sharding the resolve across typed actors by cell range and joining with
`Future.traverse`, marked *"Proposed — confirm against the existing actor
supervision before building."* A directive that is still open is exactly the
kind that gets settled locally and never written back. Settle it in the master.

## What this repository owns

The Scala implementation, its actor supervision, and its tests.
`ARBITER_ARCHITECTURE.md` here is a pointer for the same reason and to the same
place; it separates the three distinct things this system calls "arbitration" —
`outputMergeTransformation`, `arbiterRule`, and the cell arbitration registry.

## Citations

References elsewhere in this repository are prose citations of the form
`ARBITER_CONTRACT.md §5` and remain correct. Cite the section, not the
repository — a citation naming a repository is the one that goes stale when a
master moves. `README.md` cites `ARBITER_ARCHITECTURE.md` by its
`RealityEngine_CI` path, which is correct because that is where the master is.
