## Why this is a pointer

`INTEGRATION_ARCHITECTURE.md` defines the provider-neutral integration model —
the registry, the source mapper, the trigger envelope dispatcher, the dispatch
ledger, completion ingest, the MCP gateway, and the shape each provider adapter
takes. The Scala Perception Engine implements it, so it is bound by it.

This repository had no copy, which is the failure mode one step before drift, and
the same one `ARBITER_ARCHITECTURE.md` was in before it was given pointers: a
runtime implementing a contract with no local sign that the contract is written
down elsewhere. The natural repair for "I need to describe the integration model
here" is to write a local description — and then there are two masters. That is
not hypothetical here. The C++ and LSP repositories each held a copy of this
document, the three had already diverged in content rather than wording, and
neither copy was a superset of the master.

Governance has one home. `RealityEngine_CI` holds `SURFACE_SPEC.md`,
`MACHINE_CONCEPT.md`, `ARBITER_ARCHITECTURE.md`, `DEPLOYMENT_CONTRACT.md`, the
`docs/*_CONTRACT.md` files and this; `scripts/check-surface-specs.sh` enforces
that each has exactly one master and that every pointer is still a pointer.

## What this repository still owns

Its implementation of the integration model —
`src/main/scala/com/realityengine/perception/` for the routes, store and
completion path, and `perception/mqtt/MqttBridge.scala` for the MQTT bridge —
and `docs/HEALTHKIT_SPEZI_BRIDGE.md`, its device-bridge document.

The provider configuration and evidence the master does not carry live in the
worked instances it lists, and the rules those instances obey are in
`RealityEngine_CI/docs/EXTERNAL_INTEGRATION_CONTRACT.md`.
