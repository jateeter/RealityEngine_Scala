## Why this is a pointer

`MACHINE_CONCEPT.md` describes what a machine *is* — the model every runtime
implements. It was held as three byte-identical copies, one per engine
repository, with no master and nothing checking they agreed.

Three copies of one document is a document that drifts. `SURFACE_SPEC.md`
demonstrated the failure mode: kept as a canonical copy plus duplicates, two
correct parallel edits described the same rule in different words and turned
`main` red. `MACHINE_CONCEPT.md` had the same shape and no check at all, so a
divergence would have gone unnoticed rather than merely being noisy.

Governance now has one home. `RealityEngine_CI` holds `SURFACE_SPEC.md`,
`DEPLOYMENT_CONTRACT.md`, the four `docs/*_CONTRACT.md` files, and this;
`scripts/check-surface-specs.sh` enforces that each has exactly one master and
that every pointer is still a pointer.

This repository owns its implementation of the model, not the definition of it.
