# Build Control Contract

    RealityEngine_CI/docs/BUILD_CONTROL_CONTRACT.md

Do not edit this file, and do not copy the contract back into this repository.
Edit the master in `RealityEngine_CI` instead.

## Why this is a pointer

This repository is an **independent git repository** — its own history, branches
and remote. It is not a submodule or subproject of `RealityEngine_CI` or of any
other engine. It also knows how to compile itself, and `start.sh` will rebuild a
missing or stale artifact on the way up.

That last convenience is what makes the pointer necessary. Building here works,
so it is easy to assume building here is the control point. It is not: what gets
built, in what order, at which commit, with which host prerequisites checked, and
whether the result may be used in a parity or proof run, is decided in
`RealityEngine_CI` — `scripts/regression-test.sh` owns the build phase and
`scripts/verify-build-provenance.py` gates the result.

The failure this prevents is not hypothetical. On 2026-08-22 a three-engine
parity run was investigated as an engine defect for hours before anyone noticed
one repository's artifacts predated that morning's merge. A parity sweep
attributes every difference to the engines, and that is only sound if all of them
are running the code you think they are.

## Build this repository through CI

```bash
cd ../RealityEngine_CI
./scripts/regression-test.sh --build-only
```

Per-repository `make`/`sbt` invocations are for working on this repository
alone — never as the last step before a parity claim.
